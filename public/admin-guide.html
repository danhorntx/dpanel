Getting Started
Installation, first login, and overview of DPanel
What is DPanel?

DPanel is a self-hosted server control panel that runs directly on your VPS. It provides a unified web interface for managing web hosting, databases, email, file uploads, system monitoring, and more — all without paying for cPanel or Plesk.

It is built with Node.js and Express, stores sessions and user data in MariaDB, and manages server resources through system shell commands. The UI is a single-page application accessible at https://panel.yourdomain.com.

Open source — DPanel is fully self-contained. All source lives in /opt/dpanel on your server.
Installation & First Boot

DPanel is typically deployed at /opt/dpanel. After cloning the repo and installing dependencies, start it with PM2:

bash
cd /opt/dpanel
npm install
pm2 start server.js --name dpanel
pm2 save
pm2 startup

On first boot, DPanel runs an idempotent schema migration that creates the dpanel_users, dpanel_user_domains, and dpanel_audit_log tables in MariaDB. If a legacy config.json exists, the admin account is automatically migrated.

MariaDB required — DPanel uses a dedicated dpanel database. Ensure the dpanel user has full privileges on this database before starting.
Logging In
  1. Navigate to https://panel.yourdomain.com in your browser.
  2. Enter your admin username and password. The default after migration is set during initial setup.
  3. On success you are redirected to the Dashboard. Your session is stored in MariaDB and survives server restarts.
  4. Admins see the full navigation. Users with scoped domain access see only their permitted sections.
Login is rate-limited to 5 attempts per 15 minutes per IP address to prevent brute-force attacks.

To reset the admin password via the command line:

bash
cd /opt/dpanel
node -e "
const b=require('bcryptjs');
const h=b.hashSync('YourNewPassword',12);
console.log(h);
" | xargs -I{} mysql -u dpanel -pdpanel_db_secret_2024 dpanel \
  -e \"UPDATE dpanel_users SET password_hash='{}' WHERE role='admin' LIMIT 1\"
Apache Reverse Proxy Setup

DPanel listens on port 8080 (HTTPS internally). Apache proxies all traffic from panel.yourdomain.com:

apache
<VirtualHost *:443>
  ServerName panel.yourdomain.com
  SSLEngine On
  SSLCertificateFile    /etc/letsencrypt/live/panel.yourdomain.com/fullchain.pem
  SSLCertificateKeyFile /etc/letsencrypt/live/panel.yourdomain.com/privkey.pem
  SSLProxyEngine On
  SSLProxyVerify none
  SSLProxyCheckPeerCN off
  SSLProxyCheckPeerName off

  ProxyPreserveHost On
  ProxyPass        / https://127.0.0.1:8080/
  ProxyPassReverse / https://127.0.0.1:8080/

  # WebSocket terminal support
  RewriteEngine On
  RewriteCond %{HTTP:Upgrade} websocket [NC]
  RewriteRule /terminal/ws(.*) wss://127.0.0.1:8080/terminal/ws$1 [P,L]
</VirtualHost>

Navigation & Domain Switcher

The sidebar contains all panel sections. Admins see every section. Non-admin users only see sections relevant to their assigned domains.

The Domain Switcher dropdown in the topbar lets you change your active domain context. All hosting, database, and file management actions apply to the currently selected domain. Admins can switch to any domain; users only see their assigned domains.

The active domain is persisted in your session and remembered across page reloads.
Web Hosting
Apache vhosts, SSL certificates, PHP, and domain management
Adding a Domain
  1. Navigate to Hosting in the sidebar and click Add Domain.
  2. Enter the domain name (e.g. example.com). DPanel creates the Apache vhost, web root at /var/www/example.com/public_html, and log files.
  3. Point your DNS A record to the server IP. Then click Issue SSL to obtain a Let's Encrypt certificate.
  4. The domain is now live. Visit it in a browser to see the default placeholder page.

SSL Certificate Issuance

DPanel uses Certbot with the Apache plugin or webroot method to issue Let's Encrypt certificates. Certificates auto-renew via a daily cron job.

DNS must propagate first. The A record for the domain must resolve to your server IP before issuing a certificate. Use dig A yourdomain.com @8.8.8.8 to verify.
bash
# Check DNS before issuing
dig A example.com @8.8.8.8 +short

# Manual cert issuance (if panel UI fails)
certbot certonly --webroot \
  -w /var/www/example.com/public_html \
  -d example.com -d www.example.com

Redirects & .htaccess

DPanel enables AllowOverride All for every domain, so .htaccess files work out of the box. Common patterns:

.htaccess
# Force HTTPS
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# WordPress pretty permalinks
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . /index.php [L]

# Remove www
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [R=301,L]
Databases
MariaDB database and user management
Creating a Database
  1. Go to Databases in the sidebar.
  2. Click Create Database and enter a name (letters, numbers, underscores only).
  3. Optionally create a dedicated database user with a strong password.
  4. Grant the user ALL PRIVILEGES on the new database. Copy the connection string shown.
Database names are prefixed with your username automatically to avoid collisions (e.g. dan_myapp).
Database Browser v2.0

A built-in browser lets you explore any MariaDB database without leaving the panel. Click Browse next to a database in the MySQL section.

Backup & Restore

Database backups are managed through the Backups section in the sidebar. Each backup is a gzipped mysqldump stored in /opt/dpanel/backups/.

  1. Backups → Create Backup → pick a domain and type database → enter database name.
  2. To restore: find the backup file in the list → Restore → confirm target database (or new name) → type RESTORE to confirm → Restore.
"Drop and recreate target database first" is the default for cleanest restores. Without it, the import merges over the existing schema/data. Choose carefully.

WordPress Installer

One-click WordPress install via WP-CLI. Apps → WordPress → pick a provisioned domain → fill in admin email + (optional) admin user/password → Install.

The installer:

  • Downloads WordPress core
  • Creates a database + dedicated DB user with random password
  • Generates wp-config.php
  • Runs the WordPress install with your admin credentials
v2.0: Install runs as a background job. The UI polls progress and shows live status. Typical install: 60–120 seconds.
Node / Python Apps v2.0

Long-running Node.js / Python services managed by PM2 with an Apache reverse proxy. Each app gets its own port (auto-allocated 3000–3999).

  1. Upload your app code to a provisioned domain's docroot (file manager, SFTP, or Git deploy).
  2. Apps → + Deploy App → name (alphanumeric), pick the domain, runtime (Node / Python / Custom), start command.
  3. Optionally add env vars (KEY=value per line). The PORT env var is auto-injected.
  4. DPanel rewrites the domain's vhost into a reverse proxy → starts the PM2 process → live within seconds.

App row controls: Restart, Start/Stop, Logs (live stdout+stderr), Destroy (stops process + restores plain vhost).

Your app must listen on process.env.PORT (Node) or $PORT (Python/Bash). DPanel sets this — your app reading any other port will break the proxy.
Git Deploy

Apps → Git Deploy → configure a repo URL + branch per domain. Deploy runs a clean clone or pull into the docroot.

For automated deploys, point a GitHub/GitLab webhook at the deploy URL (shown in the per-domain config dialog).

The web terminal provides a full PTY shell session over WebSocket, powered by node-pty and xterm.js. It behaves identically to an SSH session.

Process Manager

The process manager shows running processes sorted by CPU or memory usage, with the ability to send signals (SIGTERM, SIGKILL) to any process. It refreshes every 10 seconds.

Killing system processes (like Apache or MariaDB) will take down hosted sites. Use with caution.

DPanel manages Postfix + Dovecot virtual mailboxes. Each domain can have unlimited email accounts. Mailboxes are stored in /var/mail/vhosts/yourdomain.com/.

  1. Go to Mail → Accounts tab.
  2. Click Add Account. Enter the local part (e.g. info) and a strong password.

Forwarders

Forwarders redirect mail sent to one address to one or more destinations without storing a local copy.

  1. Go to the Forwarders tab in Mail.
  2. Enter the source address (e.g. contact@example.com) and one or more destination addresses.
  3. Click Save. DPanel writes the alias to Postfix's virtual alias map and reloads.
Use a catch-all forwarder by entering @yourdomain.com as the source to forward all unknown addresses.
DKIM Signing

DKIM (DomainKeys Identified Mail) signs outgoing emails with a private key. Receiving servers verify the signature against the public key published in DNS, drastically improving email deliverability.

  1. Go to Mail → DKIM & DNS tab. Find your domain in the list.
  2. Click Generate DKIM Key. DPanel uses OpenDKIM to create a 2048-bit RSA key pair.
  3. Copy the TXT record value and add it to your DNS as shown below.
  4. After DNS propagation (~24h), click Verify to confirm the record is live.

Required DNS Records for Email

DKIM works alongside SPF and DMARC to form a complete email authentication chain. All three records are needed for maximum deliverability.
Webmail
Browser-based email client built into DPanel
Accessing Webmail

Webmail is available at https://yourdomain.com/webmail or via the Webmail button in the DPanel topbar. It is a standalone SPA that does not require a separate login if you are already authenticated to DPanel.

  1. Click Webmail in the DPanel dashboard, or navigate directly to /webmail.
  2. Enter your email address, IMAP password, and optionally your SMTP password if different.
  3. Click Connect. Credentials are encrypted with AES-256-GCM and stored only in your session for the duration of the browser session.
Email credentials are never stored on disk. They are encrypted in your session using a key derived from your session ID and discarded when you log out or the session expires.

Creating & Managing Users
  1. Go to Users in the sidebar (admin-only).
  2. Click Add User. Enter username and a strong password.
  3. Set the role: Admin (full access) or User (scoped access).
  4. For User role: select which domains they can manage. They only see these domains in all sections.
  5. Save. The new user can log in immediately at /login.
There must always be at least one admin account. DPanel prevents demoting the last admin to prevent lockout.
Audit Log

Every admin action is recorded in the dpanel_audit_log table: user ID, username, action type, target (domain or user), detail text, IP address, and timestamp.

sql
-- View recent audit entries
SELECT username, action, target, detail, ip, created_at
FROM dpanel_audit_log
ORDER BY created_at DESC
LIMIT 50;

-- Filter by user
SELECT * FROM dpanel_audit_log
WHERE username = 'dan'
ORDER BY created_at DESC;
Security v2.0
Two-factor authentication, API keys, audit log, and brute-force protection
Two-Factor Authentication (TOTP)

DPanel supports RFC 6238 TOTP. Works with Google Authenticator, Authy, 1Password, Bitwarden — any standard authenticator app.

  1. Settings → Two-Factor Authentication → Enable 2FA.
  2. Scan the QR code OR copy the secret string into your authenticator app.
  3. Important: save the secret in your password manager before verifying. This is your only recovery path.
  4. Enter the 6-digit code → Verify & Enable.

From then on, every login is two-step: password → TOTP code.

Lost your phone? SSH to the server and run: 
mysql -e "UPDATE dpanel_users SET totp_enabled=0, totp_secret=NULL WHERE username='admin'" dpanel
Then log in with just the password and re-enroll.
API Keys

For external automation: CI/CD scripts, monitoring, backup pipelines. Each key is a bearer token shown once at creation — only its prefix is stored after that.

Create: Settings → API Keys → Create New Key. Pick a scope:

ScopePermissions
adminFull read + write — every /api/* endpoint
readGET only — observability, monitoring, status checks

Using a key:

curl -H "Authorization: Bearer dpk_..." \
  https://panel.danhorntx.com/api/domains
API keys bypass 2FA — that's intentional for automation. Revoke any key the moment you suspect it's leaked. Every create/revoke is audit-logged.
Audit Log

Every state-changing admin action gets a row in the audit log. Browse it at Users → Audit Log (bottom of the page). Filter by action substring (e.g. backup:, apikey:, settings:).

Each entry records: timestamp, user, action, target, detail, IP.

Actions logged: user create/update/delete, settings changes (password / email / 2FA / timezone), API key create/revoke, SQL queries via DB browser, backup create/restore, app create/destroy, mail account changes.

Brute-force Protection

Two layers, both automatic:

  1. Rate limiter — 10 login attempts per IP per 15 minutes (HTTP 429 thereafter)
  2. DB-tracked lockout — 5 failed attempts in 15 minutes from one IP locks that IP for 15 more minutes. Tracked in dpanel_login_attempts.

Login history is browsable at Users → Login Attempts.

Mail Health & Deliverability v2.0
The probe that tells you if your mail will actually land in inboxes
The Mail Health Probe

SPF / DKIM / DMARC can all be "configured" but mail still ends up in spam. The probe checks every prerequisite real-world receivers (Gmail, Microsoft, Yahoo) actually look at:

CheckWhat it tests
rdnsPTR record exists for the server IP AND forward-resolves back to the same IP
heloPostfix HELO hostname resolves to the server IP via public DNS
mail-amail.<domain> A record points at the server
mxMX record present, target resolves to the server
spfSPF v1 record published, authorizes our IP, ends with ~all or -all
dkimDKIM TXT at mail._domainkey.<domain> matches the local OpenDKIM key
dmarcDMARC v1 published with a real policy (not just p=none)
mta-stsMTA-STS DNS announces policy id, HTTPS endpoint serves a valid policy file
tls-rptTLS-RPT TXT publishes a reporting address
tls-certDovecot serves a valid (non-expired, hostname-matching) cert for mail.<domain>
rblIP not listed on Spamhaus, Barracuda, SpamCop, or SORBS

Run a probe: Mail → Health tab → pick domain → Run Probe. Takes 5–10 seconds.

A daily cron at 4am UTC probes every mail-enabled domain. Results stored in dpanel_mail_health for trending. Probe failures trigger an email alert (see Notifications).

Common Failures & How to Fix
FailureAction
rdns failSet the PTR for your server IP at your VPS provider's control panel (Contabo / DigitalOcean / Hetzner) to mail.<your-domain>
helo mismatchSet DPANEL_MAIL_HOSTNAME=mail.<domain> in /opt/dpanel/.env, run configure-mail.sh
rbl listingVisit the listing service (URL in detail) to request delisting; or ask your provider for a different IP. Contabo IPs are often pre-listed
dkim mismatchMail → DKIM tab → Repair. Republishes the key from local /etc/opendkim/keys/ to DNS

DMARC Aggregate Reports

Receiving MTAs (Gmail, Microsoft, Yahoo, Mail.ru, etc.) send daily aggregate DMARC reports to whatever address your rua= tag points at. DPanel's processor reads, parses, and stores them automatically.

Setup:

  1. Create a mailbox like dmarc@yourdomain.com (Mail → Accounts → Add).
  2. Point all your domains' rua= records at it. For cross-domain rua, add <other-domain>._report._dmarc.yourdomain.com TXT "v=DMARC1" on the receiving domain (RFC 7489 §7.1).
  3. Add to /opt/dpanel/.env: 
    DMARC_INBOX_EMAIL=dmarc@yourdomain.com
DMARC_INBOX_PASSWORD=<mailbox-password>
  4. systemctl restart dpanel. Daily 4:30am cron parses anything new.

Reports are stored in dpanel_dmarc_reports. Each row: org_name, report_id, domain, date range, total/pass/fail counts, full per-record JSON.

Seed List Deliverability Test

The probe checks technical config. The seed test answers the only question that ultimately matters: did this message actually land in someone's inbox?

You configure 1–3 throwaway email accounts (Gmail, Outlook, Yahoo) with app passwords in /opt/dpanel/.env:

DPANEL_SEED_GMAIL=your-test@gmail.com
DPANEL_SEED_GMAIL_PASSWORD=<16-char-app-password>
DPANEL_SEED_OUTLOOK=your-test@outlook.com
DPANEL_SEED_OUTLOOK_PASSWORD=<app-password>
DPANEL_SEED_YAHOO=your-test@yahoo.com
DPANEL_SEED_YAHOO_PASSWORD=<app-password>

Then trigger via POST /api/mail/seedtest/run (or the UI button when surfaced). Each run:

  1. Sends a tagged message to all configured seeds
  2. Waits 2 minutes for propagation
  3. IMAP-searches each seed's Inbox + Spam folder for the tag
  4. Records where each one landed: inbox, spam, missing, or error

Restoring from a Backup

Backups → find the row → Restore. A confirmation modal asks for the target + a RESTORE typed confirmation.

Files: pick target domain. The Wipe target docroot first checkbox (default on) clears the docroot, then extracts the tar — guarantees a clean state matching the backup exactly. Unchecked, tar merges over existing files.

Databases: pick target database name. The Drop and recreate target database first checkbox (default on) drops and creates the DB cleanly before importing. Unchecked, the import merges schema/data.

Restores overwrite current state. If you might need a rollback point, take a fresh backup before restoring.
Cleanup & Retention

The Cleanup action keeps the most recent N backups per domain (default 10) and deletes older ones. Manual trigger only — no automatic retention cron yet.

Disk usage of /opt/dpanel/backups/ is visible at the top of the section.

Mobile Experience v2.0
Using DPanel comfortably on a phone or tablet
What's Different on Mobile
  • Below 768px the sidebar hides; a hamburger button (☰) appears in the topbar to toggle it.
  • Topbar tightens: hostname and clock hide below 768px, Webmail button hides below 600px.
  • Tables progressively hide low-priority columns. Domains drops Disk → Document Root → SSL as the viewport narrows.
  • Modals slide up from the bottom as full-width sheets. Cancel sits at the top, primary action at the bottom (thumb reach).
  • Touch devices get larger tap targets (32–38px minimum) on small buttons.
  • Long file paths, cert subjects, and other mono-text wrap on any boundary instead of overflowing.
Tips
  • Save to home screen for a faster launch — works on iOS Safari + Chrome Android.
  • The DB Browser works on phones but its table-list sidebar stacks above the main pane (260px sidebar would be unusable otherwise).
  • If you need to type a lot (SQL queries, Apache vhost configs), use the full-screen text editor by tapping the file → Edit. The textarea fills the modal.
  • For Terminal access on mobile, a real SSH client (Termius, Blink) is generally better than the browser-based one.

Updating DPanel
  1. Pull the latest code from GitHub.
  2. Install any new dependencies.
  3. Restart the DPanel process. Schema migrations run automatically on boot.
bash
cd /opt/dpanel
git pull origin main
npm install --production
pm2 restart dpanel
pm2 logs dpanel --lines 30  # Check for errors
The update process is zero-downtime for the web server (Apache). Only DPanel itself restarts — hosted sites remain online.
Full Server Backups

For complete server backups, back up the following locations:

bash
#!/bin/bash # Full DPanel backup script DEST="/opt/backups/$(date +%F)" mkdir -p "$DEST" # Web files tar czf "$DEST/www.tar.gz" /var/www/ # All databases mysqldump -u dpanel -p'dpanel_db_secret_2024' \ --all-databases | gzip > "$DEST/all-dbs.sql.gz" # DPanel config & source tar czf "$DEST/dpanel.tar.gz" /opt/dpanel/ # Mail spool tar czf "$DEST/mail.tar.gz" /var/mail/vhosts/ # SSL certs tar czf "$DEST/certs.tar.gz" /etc/letsencrypt/ echo "Backup complete: $DEST"
Firewall & Security

Recommended UFW rules for a DPanel server:

bash
ufw allow 22/tcp # SSH ufw allow 80/tcp # HTTP (certbot + redirect) ufw allow 443/tcp # HTTPS ufw allow 25/tcp # SMTP inbound ufw allow 587/tcp # SMTP submission ufw allow 993/tcp # IMAP SSL ufw allow 110/tcp # POP3 (optional) ufw allow 995/tcp # POP3 SSL (optional) ufw deny 8080/tcp # Block direct DPanel access (use proxy) ufw enable ufw status verbose
Block port 8080 externally. DPanel should only be accessed via the Apache reverse proxy. Exposing port 8080 directly bypasses SSL and allows unencrypted access.
